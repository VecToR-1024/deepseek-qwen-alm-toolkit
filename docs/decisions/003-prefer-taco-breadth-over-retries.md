# ADR-003: TACO 扩采优先覆盖新题，而不是重复盲采失败题

## 状态

Accepted

## 日期

2026-07-28

## 背景

TACO pilot v1 对 100 个任务最多进行了三次无反馈盲生成，共产生 220 次
attempt，只获得 47 个唯一通过任务。随后对 18 个在 4096 tokens 触顶的任务
进行了最多两次 8192-token 重试，共增加 42 次 API 调用，但只新增 2 个唯一
通过任务。

这些重试严格不向教师暴露测试、断言、stderr 或 traceback，因此不会形成基于
失败原因的纠错信号。低温下对同一 prompt 的重复生成也高度相关。对于当前目标
——扩大可用于 SFT+ALM 的题目覆盖——继续对同一批困难题增加 attempt 或输出
长度的边际收益低。

## 决策

后续 TACO 扩采采用广度优先策略：

- 从尚未采集的 train 任务中确定性抽取新题；
- 每个任务只请求一次教师生成；
- 每次请求仍执行完整 trace 校验、源码提取和隔离测试；
- 通过的任务进入候选集，失败 attempt 原样保留但不自动重试；
- 保持 `max_tokens=4096`，不因单题失败自动提升输出上限；
- 排除已确认接口不可直接执行的 `geeksforgeeks` pseudo-stdin 行；
- 不向教师提供任何 verifier 反馈。

首个版本化 campaign 固定为 1,000 个新任务，seed 为 `20260728`，并排除
TACO pilot v1 已选择的 100 个 task ID。

## 备选方案

### 保留每题最多三次盲生成

- 优点：可能在少量随机失败题上增加通过率。
- 缺点：pilot 中额外 191 次调用只增加 5 个唯一通过任务；覆盖面和成本效率差。
- 结论：不作为当前主采集策略。

### 对失败题提供测试反馈后纠错

- 优点：可能显著提高单题通过率。
- 缺点：改变数据生成协议，并引入测试泄漏、过拟合及 correction-data 语义。
- 结论：如需研究，应建立独立数据版本和目标，不混入当前盲采候选集。

### 继续提高到 16K/32K

- 优点：可容纳极长答案。
- 缺点：8192-token 重试中 42 次调用只新增 2 题，且 28 次再次触顶。
- 结论：不统一提高；长程序题需另行定义 eligibility 或专用 campaign。

## 后果

- 同等 API 调用预算覆盖更多独立问题，预计得到更多唯一候选和更丰富的题型。
- pass@1 可能低于重试后的累计通过率，但成本应按“每个唯一 accepted”评估。
- 失败题不会被自动修复；原始失败数据仍可用于未来独立的 correction 或
  preference 研究。
- 首批 1,000 题来自已固定 revision 的单个 train Arrow 分片，仍存在
  single-shard sampling bias，不能表述为完整 TACO train 的无偏样本。
- 该决策只改变数据采样策略，不改变 ALM trainer、loss 或学生训练协议。
